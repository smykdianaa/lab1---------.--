### 6. Пояснення призначення `subTest` та `unittest.mock`

#### 🔹 Призначення `subTest`

Контекстний менеджер `self.subTest()` дозволяє виконувати параметризоване тестування всередині одного тестового методу.

<< Якщо при звичайному циклі один з елементів викликає помилку, увесь тест переривається. `subTest` гарантує, що перевіряться ВСІ набори даних, а у звіті чітко вкажеться, який саме випадок не пройшов. >>

**Приклад з коду:**

```python
def test_all_figure_types_with_subtest(self):
    cases = [
        {"type": "square", "sides": (5,), "expected_length": 20},
        {"type": "rectangle", "sides": (4, 6), "expected_length": 20},
        {"type": "triangle", "sides": (3, 4, 5), "expected_length": 12},
    ]
    for case in cases:
        with self.subTest(figure_type=case["type"]):
            fig = Figure(case["type"], *case["sides"])
            self.assertEqual(fig.get_figure_length(), case["expected_length"])

```

#### 🔹 Призначення `unittest.mock` (`patch`)

Декоратор `@patch` використовується для ізоляції тесту від зовнішнього середовища (підміна введення з клавіатури, мережевих запитів, файлової системи чи поточного часу).

<< Завдяки `@patch("builtins.input", return_value="5")` функція `input()` не зупиняє виконання програми в очікуванні дій користувача, а автоматично повертає значення `"5"`. >>

**Приклад з коду:**

```python
@patch("builtins.input", return_value="5")
def test_get_user_figure_length(self, mock_input):
    result = get_user_figure_length()
    self.assertEqual(result, 20.0)  # Периметр квадрата 5 * 4 = 20.0
    mock_input.assert_called_once()  # Перевірка, що input() викликався 1 раз

```
